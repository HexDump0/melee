## Older blocker (fixed): ftparts.c:793 "can't find tobj!"

`ftAnim_80070200` calls `ftParts_80075240(fp->dobj_list, r5->x5D0[i])`
(`ftparts.c:1014`) and the lookup fails. gdb showed the requested index
`n = 3840 (0x0F00)`, i.e. a **big-endian u16 that was not converted**.
`x5D0 = ftData->x8->x8.xC[costume_id]` — the per-costume `u16` TObj-index
arrays. `conv_ft_data` converts them (`cost_tbl`, `n_tobjs = x8_x8.x8`) but
the runtime value proves either the count used for the loop was wrong or the
array walked is a different one. With `ftData->x8` pointing at **data offset
0** (G-023) the offsets are: `FtPartsDesc.model_num @0`, `vis_table @4`,
`x8_x8.x8 @8`, `x8_x8.xC @0xC`. For `PlMr.dat`: model_num=1, vis_table=0x6eb8,
x8=2, xC=0x6f0c; `xC[0]=0x6f08` and the raw u16 there is 0x000E (14), yet the
runtime read 0x0F00. Next step: gdb `x/8hx` on `r5->x5D0` and compare with the
raw file at 0x6f08; verify whether `fp->x619_costume_id` indexes a different
entry (`xC[1..]` are 0 in the raw file, so the fallback should pick `xC[0]`).
