# Handoff: P-648 menu BGM stops after ~3 s (BLOCKED 2026-09-13)

> **Resolved 2026-09-13 (opencode/deepseek-v4.1-flash).**  Three host-only
> causes; full evidence in `logs/2026-09-13-P-648-hps-ring.md` and gotchas
> G-115..G-117.
> 1. `AXSetVoiceAddr`'s `COPYADDR` was coalesced with
>    `HSD_Synth_8038B120`'s address-field sync bits inside one 5 ms frame, so
>    `__AXServiceVPB` took the per-field branch and the shadow never saw the
>    header `loopFlag`.  Fixed by collapsing to `COPYADDR` in
>    `native/audio/ax_hle.c` (`ax_collapse_addr_sync`).
> 2. The mixer's `frame_addr >= end_addr` test re-wrapped on every frame while
>    the game's `endAddress` lagged the next-page loop target (a ~2.3 kHz
>    buzz).  Fixed by crossing semantics (`prev_frame_addr < end`).
> 3. `hps_fix_read` never byte-swapped the page table's `AXPBADPCMLOOP`
>    predictor contexts, so the mixer loaded swapped `yn1/yn2` at each seam.
> Page machine now advances 0→1→2→… (46+ reads in 1400 frames, zero node
> teardowns); music sustains through 22 s and `ctest` is 15/15.

## Established facts (all gdb-verified, 32-bit relays noted per-probe)

1. **Exactly 16 HPS reads, all `menu01.hps`, all before frame ~700, then
   zero forever:** header (`off=0`), 3 page tables (`0x80`, `0x100a0`,
   `0x200c0`, all convert correctly: `x0=0x10000`, `x8` chain sane),
   12 data chunks (3 full pages into ARAM `0x619ea0/0x5f9ea0/0x609ea0`).
2. **Page machine deadlocks at `(7768,776C,7778)=(1,1,0)`, `pos=2`.**
   Full trajectory over 950 frames is 5 states: `(2,2,0)` → `(0,0,0)` →
   `(1,1,0)` all at frame 660 (initial burst, correct), then frozen.
   (`HSD_Synth_804D7768/6C/78/70/74`, `lbl_804C4540[3]`.)
3. **Playhead frozen:** voice currentAddress advances normally *within*
   the start slot (`0xc33df8`→`0xc414f8`, correct rate) but never leaves
   it; `pos` reads 2 from entry to death. User↔shadow readback verified
   working (1-frame lag) — NOT the bug.
4. **Death:** both stream voices hit mixer end (`endAddr`, loopFlag=0 in
   shadow) ~frame 767; node 317 torn down by `HSD_SynthCallback`'s
   `voice[0].state==0 && voice[1].state==0` check (caught via watchpoint:
   `HSD_SynthSFXStopNode` from `HSD_SynthCallback`). Mixer never at fault;
   no DVD/DevCom errors; ASan-adjacent paths fine.
5. **Teardown is game-driven and "correct"** given the frozen endAddrs —
   the bug is upstream: end never extends + loop never engages because
   both require a `pos` transition that can't happen while end caps the
   voice in its start slot (circular deadlock, `synth.c` `HSD_Synth_8038ADD0`
   + `_inline`).

## Ruled out (with evidence)

- Mixer end/loop handling (`ax_mixer.c` `voice_decode_frame` – logic sane;
  never fires spuriously; 19k `oob` ends at frames 239–767 are boot-SFX
  churn, pre-existing).
- DVD/CISO reads, `hps_fix_read` shapes (all exact-match converted),
  page-table endianness, ARQ slot exhaustion (linked-list queue, no cap),
  completion-pump reentrancy (`complete.c` handles it; 721 ARQ ISRs drain).
- DVDClose/DVDCancel over-cancellation (frame-660 cancels target unrelated
  stack blocks; DevCom blocks untouched).
- `TexAnim`-style converter miss on the audio path (tables verified sane
  in live memory).
- Readback/user-vs-shadow divergence (verified tracking; earlier scare was
  a probe offset bug: AXPBADDR curHi/Lo are at VPB+0x138+0xC/+0xE, and
  compiled `AXVPB.pb` is at +312=0x138 per `ptype /o`).

## Open question (what blocks the fix)

Why does retail escape the same circle? Same code+data should deadlock
identically: end covers ~1 page, loop is off in shadow (only
`AXSetVoiceLoop(...,0)` exists in game code), `pos` starts in its slot.
Prime suspects, untested:
1. Initial `loopFlag`/loop-addrs differ via pool garbage (host calloc
   vs console residue) — weak, since shadow flag reads 0 on both by
   construction.
2. The `pos == 7770` loop-engage block is supposed to fire during the
   initial burst (it did fire once: 7770 went 2→0) — maybe on console a
   second firing (different completion order from slow DVD) sets up the
   rotation. Host completes the whole burst inside frame 660.
3. `x4 = 0xffff` may be a sentinel meaning "to end of stream" that
   some path honors — no such path found.
4. Match/boot long streams may be equally broken on host (a 700-frame
   `--audio-dump` WAV shows energy collapse after ~3 s, but SFX
   confound it) — if universal, the defect is deterministic, not a race.
