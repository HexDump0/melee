# Handoff: P-627 fixed — convert `ftData_x58_t` leg-IK lengths

**Date:** 2026-09-12
**Agent:** codex
**Commit:** this commit
**Tree state:** clean full build, ctest 12/12, 600-frame ASan boot-match clean

## What was wrong

P-629 (`381ec2f68`) stopped the ~29 ms NaN-processing plateau but did **not**
fix Link's legs; its handoff/STATE/log overclaimed the pose. Link's leg
matrices were still NaN at frame 720.

The NaN originates in the ground IK, not in GX or the JObj animation walk:

1. `ft_80089B08` (`src/melee/ft/ft_0899.c:95`) reads the two-bone leg lengths
   from `((ftData_x58_t*) fp->ft_data->x58)->x4/xC/x18`.
2. `native/decomp/assets/hsd_convert.c` never converted that struct. The three
   f32 fields stayed big-endian on disc, so the host read
   `x4=-490.4`, `xC=-1.01e27`, `x18=7.72e35` (part indices `x0/x1/x8/x9/x10/x11`
   are bytes and were fine).
3. `pos3/pos4` (`ft_80089B08`) then exploded to ~1e35. In
   `lbBgFlash_80021410` (`src/melee/lb/lb_020A.c`), `len_ac` came from squaring
   an overflowing value, `cos1/cos2` went NaN, and `fn_8002113C` wrote NaN
   rotations into Link parts 6–10 and 12–16.
4. `ft_80089B08` restores the saved rotations afterwards without dirtying the
   matrices, so in states that don't re-set-up the leg joints (Wait,
   LandingAirF) the NaN `mtx` survived to render: finite rotate/scale, NaN
   rotation matrix, finite translation — exactly the P-627 signature.

GDB on the pre-fix build caught NaN `angle` at `fn_8002113C` from frame 190
onward; the first matrix-NaN frame was 671, then 695–720. A probe of
`ft_data->x58` showed the raw values above; byte-swapping them gives
`2.89 / 3.88 / 1.36`, matching Link's leg proportions.

## Fix

`native/decomp/assets/hsd_convert.c` (converter v58) adds the missing
`ftData->x58` walk:

```c
uint32_t x58 = rd32(c, off + 0x58);
if (x58 != 0 && in_data(c, x58, 0x1C)) {
    conv_u32(c, x58 + 0x04);
    conv_u32(c, x58 + 0x0C);
    conv_u32(c, x58 + 0x18);
}
```

Bump `HSD_CONVERTER_VERSION` so stale caches regenerate.
