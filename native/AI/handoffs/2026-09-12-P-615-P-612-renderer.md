## What I did

- **P-615 (done).** `GXCopyTex` is captured as a command in the frame stream
  and gx_gl reads the EFB back at that point, re-encoding RGB565/RGBA8 tiled
  memory so the CPU texture decoder sees a normal texture.  `GXSetZTexture`
  (REPLACE/ADD) runs a small dedicated depth-only program (G-068) that samples
  the bound texture as the Z source, matching `HSD_EraseRect`'s constant Z8
  dummy.  Added GX_TF_Z8 decode.  Two real fixes came out of it: direct-mode
  primitives now flush before any draw-state setter (G-069, this is what makes
  HSD's `GXEnd`-terminated erase pass snapshot correctly) and recycled
  `frame_draws[]` slots are zeroed (G-070).  New ctest `decomp_efb`.
- **P-612 (done for the character-visible part).** The NBT reader keeps
  binormal/tangent, the vertex transform normalises them, and `GX_TG_BUMP0..7`
  implements the hardware emboss formula (Dolphin `EmbossMap`): source coord +
  light direction projected on tangent/binormal.  `resolve_stage_coords` no
  longer folds bump coords, which is what made Giga Koopa's TEV add/sub pair
  cancel — it now renders green/orange instead of magenta.  Fragment stages
  gained `v_uv2` for coord 2.  The indirect-texture setters now capture state
  per draw (P-617 evaluates it in S4).
- **P-616 (still open, narrowed).** Captain Falcon's eyes are a TEX1 overlay
  on batch 96 / dobj 77 (`PlCaNr.dat`), the only 2-TObj material.  Ruled out:
  visibility, culling, alpha test, KONST tables.  The geometry draws (wireframe)
  but its TEV result is black; the same 4-stage template works for body
  specular maps, so the next step is tracing that one draw's stage-2 sample.

## What I tried that did not work

- **Writing `gl_FragDepth` from the big TEV shader.** Uniforms and control flow
  verified with debug colors; the depth buffer never changed.  A minimal EGL
  shader works, so it is a driver/program-size interaction (G-068).  The
  dedicated ztex program is the fix.
- **"Fixing" the KONST component select (P-614).** The original P-614 mapping
  is algebraically identical to the correct `K0_R..K3_A` layout; the apparent
  bug was a misread.  Reverted; do not chase it for P-616.
- **Isolating the Falcon head by part index.** The hand parser's batch order is
  descriptor order, HSD draws in joint-tree order, so `--part N` differs
  between the prototype and compiled viewers.  Use texture/material state, not
  indices, to correlate.
- **`GXSetZTexture` as an FBO/EFB depth sample.** Not needed for the current
  content: HSD's only user binds a constant Z8 dummy, so sampling the bound
  texture is faithful and avoids an offscreen EFB refactor.
