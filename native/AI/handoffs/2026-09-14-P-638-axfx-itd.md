## What I did

- Transcribed `reverb_hi` to C: pre-delay, three feedback combs, three series
  allpasses, the 0.3 one-pole low-pass with `lpLastout` feedback, the
  `0.6*level` dry/wet mix and the `ps_muls0`-only right-channel crosstalk.
  Init/Settings/Shutdown/Free follow the SDK C scaffolding.
- Transcribed `chorus`: the 512-float `rsmpTab12khz` table plus `do_src1`/
  `do_src2` (32-bit phase accumulator, carry into `posHi`, `trigger`/`target`
  ring wrap, FIR history) and the SDK's pure-C callback/Settings/Init.
- Confirmed the chorus phase extraction against the retail DOL: the asm
  `rlwinm r10,r4,7,21,27` encodes `54 8a 3d 76`, present at 0x359b34 and
  0x359ccc, so the PPC rotate+mask semantics are correct (a plain
  `(posLo >> 14) & 0x7f` would be wrong).
- Refined the mixer ITD: `shiftL/shiftR` step toward their targets once per
  5 ms frame (before the sample loop) instead of once per sample, matching the
  game's snap-vs-target split in `HSD_SynthSFXUpdateMix`.
- `test_audio` gained `test_axfx_effects` (install malloc/free hooks, run one
  buffer through each effect, require bounded output, Settings rebuilds the
  work buffers, Shutdown frees) and satisfies axfx.c's default OS-heap
  references with local stubs.

## What I tried that did not work

- Implementing `rlwinm r10,r4,7,21,27` as `(posLo >> 14) & 0x7f`: that is not
  what the instruction computes.  A brute-force search over (SH,MB,ME) for a
  monotonic phase found SH=11, but the retail DOL has no `54 8a 5d 76` and two
  `54 8a 3d 76`, so the SDK source and the PPC semantics both stand.
- Linking the unit test without OS-heap stubs: axfx.c's default hooks
  reference `__OSCurrHeap`/`OSAllocFromHeap`, so the test now defines them
  (and installs its own `AXFXSetHooks` allocator).
