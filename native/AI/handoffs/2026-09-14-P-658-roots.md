## What I did

- `standScene` (GmRgStnd.dat) and the GmRegEnd.dat cutscene symbols
  (`cut1CanimScene`, `cut2CanimScene`, `cut3CanimScene`, `cut3BgScene`) are
  `SceneDesc`s and now dispatch to `conv_scene_desc`; the dispatch compares
  the real symbol length (`standScene` is 10 chars — the first attempt used 9
  and silently did nothing).
- `gmIntroEasyTable` (GmIntEz.dat) converts the f32 rows of the Classic intro
  layout: slot rows x00/x18/x3C and x630/x654/x678, `ClassicCharLayout` rows
  x6C/x6A8, `ClassicTeamEntry` x37C and `ClassicSplashRow` x57C, skipping the
  unnamed pad runs.
- `sqEventInitDataLevelTbl` (GmEvent.dat) walks the relocation-bounded array
  of 51 levels: each level's evinit, evbonus, stage table and five
  player-init blocks.  `gm_evinit`'s first word is MWCC MSB-first bitfields,
  so the converter repacks the two bytes to GCC's LSB-first layout
  (0x2b800102 -> host bytes 0xD1/0x01); the level `+0x04` pointer is dual-use
  (level-0 timer numerics vs a character-kind byte list) and stays raw.
- `dbLoadCommonData` (DbCo.dat) is three `char**` name tables, so its branch
  is explicit but only the relocation pass acts.
- `test_decomp_assets` adds raw-vs-converted checks for the camera near/far
  of both scene roots, the first Classic row, and the level-0 flags +
  `unk24`; disabling a branch fails the check on the first value.

## What I tried that did not work

- Symbol lengths: `standScene` (10) and `gmIntroEasyTable` (16) were first
  written one short, and the branches never matched.  The first test run
  showed denormals (`7.11e-41`) and an unconverted 0xC0 raw word; the
  diagnostic values in the check made the mismatch obvious.
- Converting the event `+0x04` target as `{int x0; int x4}`: it is the same
  address as a `gm_event_char_list` byte array for multi-opponent levels
  (gm_801BAC9C), so a byte swap would corrupt the character list.
