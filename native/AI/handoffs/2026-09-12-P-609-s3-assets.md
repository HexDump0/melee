## What I did

- **DVD/ARAM/DevCom.** `platform/dvd.c` mounts the disc image (`MELEE_DISC` or
  the default path), loads the FST into the GC boot-info page and runs the
  decompilation's own `extern/dolphin/.../dvd/dvdfs.c`. `platform/ar.c` plus
  the compiled `arq.c` implement 16 MB host ARAM with console offset
  semantics; `ARStartDMA` copies and posts the DMA completion.
  `platform/complete.[ch]` is the deferred completion queue, drained when
  `OSRestoreInterrupts` re-enables interrupts or on `VIWaitForRetrace`.  This
  ordering matters: DevCom/ARQ set their busy flags *after* issuing a request,
  so inline callbacks re-enter and stall them.
- **Generic converter.** `decomp/assets/hsd_convert.[ch]` replaces the S2
  `hsd_scene.c` walker.  It swaps the header/tables, then every relocation
  target (the authoritative pointer list), then the numeric fields of the
  known classes; byte-defined ranges are never written.  `stats.ok`
  (`reloc_valid == reloc_total`) is the desync detector.  A content-hash +
  version disk cache (`MELEE_ASSET_CACHE`, `MELEE_NO_ASSET_CACHE`) keys the
  converted image.  The decomp shim renames `HSD_ArchiveParse` so every
  compiled parse converts first.
- **Format knowledge added.** `.ssm` header + stream-table record counts
  (`platform/ssm.c`), scene data (`SceneDesc` models/cameras/lights/fogs),
  `HSD_CObjDesc`, `HSD_LightDesc` (+union), `HSD_FogDesc`, `HSD_WObjDesc`,
  RObs, FigaTrees and the animation trees.
- **Boot.** It now passes the sound-bank wait and loads `NtMsgWin.dat` /
  `SdMsgBox.usd` through the compiled loaders, then waits for a pad event in
  `gm_Scene_MemCard_OnFrame` (input is S4; the watchdog ends the run).
- **Tests.** `test_decomp_assets` (ctest `decomp_assets`): 33/33 `Pl*Nr.dat`
  plus `GrNBa`/`MnSlChr`/`IfAll`/`NtMsgWin` load with full reloc coverage and
  a successful joint pose, plus a cache round-trip.

## What I tried that did not work

- **Inline completion callbacks.** They re-enter `HSD_DevComDVDWakeUp` before
  `HSD_DevCom_804D77F5` is set and deadlock; that is why the pump exists.
- **Converting whole files at DVD read time.** `lbFile` reads in 0x80000
  chunks via DevCom, so only the first chunk starts with an HSD header; the
  `HSD_ArchiveParse` shim is the only hook that sees whole (sub-)archives,
  including the copies ftData makes out of ARAM.
- **Two separate buffers (S2 style).** In-place conversion is required for the
  cache and the `HSD_ArchiveParse` hook; the trade-off is that every walker
  needs a `mark()` idempotence guard (the shared vtxdesc lists and envelope
  lists are visited once per owning PObj).  Missing guards double-swapped
  values and produced the spike geometry seen mid-session.
- **Reading scene data only by root name.** `SdMsgBox.usd`/`NtMsgWin.dat` have
  no `_joint` root; `*_scene_data`/`*_scene_models` dispatch was needed.
- **ASan's `dvd_run_completion` EBX=0 crash** looked like an ABI bug; the real
  cause was `DVDCancel` deferring a write into a caller-stack `DVDFileInfo`
  (fixed, G-063).
