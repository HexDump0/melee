# Architecture decision log

Append-only. Never edit an accepted decision; supersede it with a new one.
Format: `ADR-NNNN: Title` with Context / Decision / Consequences / Status.

---

## ADR-0001: Hand-written C sandbox instead of compiling the engine first

**Context.** The decomp sources are GameCube-specific (MWCC, 32-bit pointer
assumptions, GX hardware calls, `Runtime/platform.h`). Compiling them wholesale
on a 64-bit host was not viable in the time available, and the goal was a
runnable demo that proves the asset pipeline.

**Decision.** Build a small independent C sandbox under `native/` that reads raw
HSD bytes and renders them. The decomp is used as documentation for formats and
formulas, not as a compiled dependency (yet).

**Consequences.** Fast progress and 64-bit safety, but every HSD behavior must
be re-derived (skinning, animation, TEV). Those derivations are documented in
`learnings/`. P-301 begins pulling real math back in.

**Status:** accepted (2026-09-09).

## ADR-0002: Raw bounds-checked parser over HSD data, no host pointer casts

**Context.** HSD archive pointer fields are 32-bit offsets. On the GameCube,
relocation turns them into real addresses. A naive port casts them to host
pointers and breaks on 64-bit.

**Decision.** Never cast. Every accessor translates a 32-bit data-relative
offset into a host file offset (`+0x20`) and bounds-checks the read. NULL-vs-
base-0 ambiguity is resolved per field (`rptr` vs `rbase`).

**Consequences.** Slightly verbose parser, but portable, fuzzable, and safe on
any word size. This is the foundation for a future WASM target.

**Status:** accepted (2026-09-09).

## ADR-0003: Reproduce bind pose with the HSD rigid/blended envelope rule

**Context.** Raw vertex positions render as a blob. Investigation showed the
correct behavior is in `HSD_PObjSetupMtx`: groups with first weight 1 use
`M_joint` directly; blended groups use `sum(w * M * inverseBind)`, which is the
identity at bind pose. The group index is `PNMTXIDX / 3` because `PNMTXIDX` is a
GX matrix slot (`GX_PNMTX0..9` at indices 0,3,...,27).

**Decision.** Reimplement exactly that rule for the static case, computing bind
world matrices with `HSD_MtxSRT` including parent-scale correction.

**Consequences.** Correct textured T-pose for all tested characters. The `right`
matrix (non-skeleton-root PObjs) is still missing; see P-202.

**Status:** accepted (2026-09-10).

## ADR-0004: OpenGL 2.1 fixed-function for the demo renderer

**Context.** Agents must verify rendering headlessly (SDL `offscreen` + Mesa),
and the eventual demo should run on weak hardware. Modern core profiles require
shader plumbing and behave differently across drivers.

**Decision.** Use OpenGL 2.1 with `glBegin`/display lists and fixed-function
lighting for now. Move shaders in only when TEV fidelity demands it, and keep a
headless-compatible path.

**Consequences.** Fast iteration and reliable screenshots. The renderer is not
extensible to real TEV; that work is scheduled as P-204/M3.

**Status:** accepted (2026-09-09).

## ADR-0005: Assets are never committed

**Context.** This repository is a decompilation project and already treats ROM
data as user-supplied (`orig/*` is git-ignored).

**Decision.** The port reads the user's disc image at runtime. Tests that
require assets must be clearly marked and skipped without a disc. Synthetic
fixtures may be generated by scripts but must contain no game data.

**Status:** accepted (2026-09-09).

---

## ADR-0006: Per-frame animation will require a renderer restructure

**Context.** The current renderer bakes the bind-pose triangle list into one GL
display list. Animation needs per-joint transforms per tick.

**Decision.** When P-201 starts, keep `demo_model` as the parser and split its
output into per-PObj primitive batches tagged with their rigid group (or blended
joint set). Apply joint matrices at draw time. Do not pre-transform on the CPU
per frame unless profiling shows it is cheap enough at 60 Hz for two fighters.

**Consequences.** The bind-pose fast path stays for `--view`; the gameplay path
gains a per-joint draw loop. Verifiable with the existing `--scripted`
screenshot harness.

**Status:** proposed (2026-09-10).

---

## ADR-0007: Linux native is the reference target; WASM is a later decision

**Context.** The owner wants PC, WASM and "other stuff". Doing all at once
would slow progress.

**Decision.** Keep the platform layer thin (SDL2 + OpenGL + libm) and avoid
Linux-only APIs so a WASM port is possible. Write the WASM feasibility memo
(P-502) before attempting it.

**Status:** accepted (2026-09-09).
