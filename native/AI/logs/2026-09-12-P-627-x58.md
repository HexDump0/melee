# P-627 Link leg investigation

Goal: find the upstream source of Link's NaN leg matrices at match frame 720,
which P-629's host-FP work left in place.

## Reproduction

```sh
SDL_VIDEODRIVER=offscreen ./build/native/melee_decomp_viewer \
  --match --frames 720 --dump-draws 720 --shot /tmp/p627-dump.bmp
```

Pre-fix, 14 draws reported the inverted sentinel NDC bounds. Ten were Link's
legs (draws 117–121 and 135–139); the other four (8, 10, 13, 15) were also
poisoned by Link's NaN matrices in the same frame.

## Matrix probe (GDB, `VIWaitForRetrace` frame counter)

Reading `player_slots[0]` -> `Fighter.parts[i].joint.mtx` each frame:

```text
frame 650..670  motion 27/66/71  all-finite
frame 671..673  motion 71        NaN-parts=[6,7,8,9,10,12,13,14,15,16]
frame 674..694  motion 15/16     all-finite
frame 695..720  motion 14        NaN-parts=[6,7,8,9,10,12,13,14,15,16]
```

So the NaN was written earlier and only *survived* to render in states whose
animation does not re-set-up the leg joints. `ft_80089B08` saves the leg
rotations before IK and restores them after (`rot_save*`), but the restore is a
plain struct assignment (no `HSD_JObjSetMtxDirty`), so a poisoned `mtx` stays.

## Angle probe

Breaking on `fn_8002113C` (the arbitrary-axis rotation writer) and checking
`angle != angle` showed the pre-fix build feeding NaN angles from frame 190
onward. Example frame 190, jobj 0x808d2f40 (part 12 chain):

```text
angle=nan  axis=(0.285,-0.146,-0.947)
caller lbBgFlash_80021410 -> ft_80089B08 -> Fighter_8006C5F4
angle1=1.57079637  angle2=1.32917118
data pos0=(-60.58,6.01,0.75) pos1=(-57.20,6.36,1.71) pos2=(-58.01,1.73,2.09)
data pos4=(-1.37e+35,-7.56e+35,7.52e+34)  len1=-nan
```

`pos4` was finite but astronomically large, not NaN on entry, so the
non-finite check at function entry missed it. `pos3` (the unprojected target,
set by `ft_80089B08`) was ~1.33e+35.

## Source

Reading Link's IK table in the same breakpoint walk:

```text
x58 x0=12 x1=6 x4=-490.439453 x8=13 x9=7 xC=-1.01293344e+27
    x10=15 x11=9 x18=7.71994066e+35
```

The part indices are correct, but `x4/xC/x18` are byte-swapped floats:

| raw LE read | byte-swapped (big-endian) |
|---|---|
| `-490.439453` | `2.8900001` |
| `-1.01293344e+27` | `3.8800001` |
| `7.71994066e+35` | `1.3600000` |

`native/decomp/assets/hsd_convert.c``conv_ft_data` walked every other
`ftData` sub-table (`x0`, `x8`, `xC/x14`, `x24`, `x2C`, `x30`, `x34`, `x38`,
`x3C`, `x44`, `x50`, `x5C`) but never `x58`. With lengths ~1e35, `pos3` is
`pos1 + normalized * len1` ~1e35, and `lbBgFlash_80021410`'s triangle solve
(`len_ac` squares it) overflows to `inf`/`NaN`, so `acos` -> NaN -> NaN
rotations.

## Fix and verification

`hsd_convert.c` v58 converts `x58+4`, `x58+0xC`, `x58+0x18`
(`HSD_CONVERTER_VERSION` bumped to invalidate cached assets). Post-fix:

- `x58` reads `x4=2.89 xC=3.88 x18=1.36`.
- NaN-angle probe: 0 hits over 720 frames.
- Matrix probe: 71/71 probed frames finite (650–720).
- `--dump-draws 720`: 0 sentinel NDC bounds in 223 draws; leg draws
  (117–121, 135–139) have normal NDC boxes.
- `/tmp/p627-dump.bmp` (before) shows the broken lean/missing leg;
  `/tmp/p627-fixed.bmp` (after) shows both legs and an upright pose.
- `--match --frames 1200`: game work 2.0–7.1 ms over frames 600–1200.
- ctest 12/12; 600-frame 32-bit ASan/UBSan boot-match clean.
