# P-629 host floating-point investigation

> **Correction (2026-09-12, P-627):** this log's claim that the frame-720 pose
> was coherent is wrong. The `__frsqrte` fix removed the sustained slowdown,
> but Link's legs still went NaN. A second NaN producer (unconverted
> `ftData->x58` IK lengths) was found and fixed later the same day; see
> `2026-09-12-P-627-x58.md`.

The sustained frame 670–1080 slowdown was traced with temporary non-finite
counters, `perf`, and conditional GDB watchpoints.  The diagnostic counters
were removed after localization; no runtime instrumentation remains.

Key observations:

- Frame 720 had 40,239 non-finite matrix components and 23,040 non-finite
  transformed outputs but exactly the same 223 draws / 61,821 vertices as the
  preceding fast phase.
- `perf` attributed the plateau to x87 matrix/vertex arithmetic.  This was
  work performed on poisoned matrices, not a color-decoder workload change.
- The first bad Link joint came from `lbBgFlash_80021410` leg IK calling
  `fn_8002113C` with a NaN angle.
- `src/placeholder.h` incorrectly maps reciprocal-square-root estimate
  `__frsqrte` to ordinary `sqrt` for non-Metrowerks builds.
- Once that was corrected, a conditional watchpoint found a separate NaN
  write in `HSD_QuatLib_8037EF28`: x87 excess precision selected the slerp
  branch for two quaternions whose `float` dot product is 1.0, then `acosf`
  rounded its argument to 1.0 and the code divided by `sin(0)`.

Final offscreen 1,200-frame capture (`/tmp/p629-fixed-1200.log`) sampled game
work between 1.4 and 5.8 ms over frames 600–1200.  Frame 720 was 2.18 ms game,
4.06 ms process CPU and 1.86 ms GL render.  The frame-720 BMP/PNG in `/tmp`
did **not** show a coherent Link pose: the legs were still missing/deformed
(P-627, fixed separately).  Full ctest was 12/12 and the required 600-frame
ASan/UBSan match completed without a sanitizer report.
